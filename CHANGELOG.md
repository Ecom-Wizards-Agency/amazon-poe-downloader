# Changelog

## 0.1.0 (2026-09-24)

First public release. Node.js 22 built-ins only, no npm dependencies.

- `run-poe.mjs` talks to any Chrome started with `--remote-debugging-port`, on any host and port (default `127.0.0.1:9222`), and opens its own background tab for each run. A DevTools endpoint that accepts connections but does not answer fails after 5 s with `CDP_UNREACHABLE`.
- Commands: `doctor`, `niche`, `search`, `batch`, `merchant-niches` and `self-test`. Options take their value as the next argument or after `=` (`--marketplace=us`); an unknown, repeated, empty or missing required option, an extra argument, `--marketplace-label` or `--parent-account-name` without `--account-name`, or `batch` with both `--queries` and `--query` or both `--top` and `--all`, stops the run with `POE_ARGUMENT_INVALID` before the output folder, the run lock or Chrome is touched.
- Output goes to a local folder (`--out-dir`, `POE_OUT_DIR` or `./poe-output`, with an optional `--label` subfolder). Files are never overwritten, and each data command that stores a file prints one JSON receipt with the SHA-1 of every stored file.
- Before Chrome is contacted, a data command's `--origin` must be a known Seller Central https origin (`POE_ORIGIN_UNKNOWN`) in the same region as `--marketplace` (`ORIGIN_MARKETPLACE_REGION_MISMATCH`). `doctor` still requires a known origin but reports another region as `Marketplace: WRONG REGION`.
- One data command at a time per Chrome endpoint, enforced by an owner-only lock file in the system temp folder (`POE_RUN_IN_PROGRESS`). The lock is linked into place with its full body where the file system supports hard links; otherwise it is created exclusively, and an unreadable lock younger than 5 s is never reclaimed. Loopback host spellings share one lock. A stale lock is reclaimed only under a reclaim guard file: the lock is renamed to a unique tombstone and deleted only if it is the same file that was judged stale, otherwise it is linked back (renamed back where hard links are unsupported). If another lock took the name in the meantime, the tombstone is kept and the run stops with `POE_RUN_IN_PROGRESS`. A lock naming the run's own process id that the run does not hold (a reused id after a crash) is stale. The busy message names the lock file.
- Account safety: the active account is read and checked against `--account-name`, `--expected-partner-account-id` and `--expect-account` before any data request. `--marketplace-label` and `--parent-account-name` steer the account picker; with `--account-name` and `--marketplace-label`, a mismatch can be switched through Seller Central's account picker, which changes the session's selected account and marketplace.
- Before and after each request, the account, the session marketplace and the exact page origin must be unchanged (`POE_CONTEXT_CHANGED`). The baseline is read once POE is ready, after the account header had up to 10 s to render. The ids and the marketplace are compared exactly; the display name is compared only when no strong id is available, because it comes from the page and can render late. The display name is read only from the account header or the account picker, never from the Account Health widget. After each request, the marketplace id the response reports must equal `--marketplace`; an empty search or merchant-niches result has nothing to compare. A niche response must report the requested niche id (`POE_NICHE_MISMATCH`).
- A `batch` with failed niches prints an `incomplete` receipt that lists the stored files and the failed niches, and exits 1. A rejected niche response or a CDP timeout stops the batch and lists that niche under `failed`; the niches the batch had not finished, including one cut short by an interrupt, are listed under `pending`. `--top` limits the search niches only; every `--niche-ids` entry is downloaded. A run that fails partway through storing a file set also prints an `incomplete` receipt listing the files already stored, and so does `format-poe.mjs --stdin`. A failed or interrupted run exits only after its receipt is written, so a receipt larger than a pipe buffer arrives whole.
- `doctor --quick` rejects `--origin` (`POE_ARGUMENT_INVALID`), because it judges only the open tabs. Without `--quick`, `doctor` checks a fresh POE tab even when the open tabs are stale or signed out, and with `--marketplace` it also checks that marketplace's domain when no open tab is in its region. `doctor --quick` with no open Seller Central tab reports that login is not verified without claiming to check an origin. `doctor` gives the account header the same 10 s before it prints the `Active account` line, prints an error without a code under the `POE_NOT_READY` label, prints an unreachable Chrome as `Chrome: not reachable (CDP_UNREACHABLE)`, and `format-poe.mjs` prints the error code (for example `POE_FORMAT_INVALID`) before its message.
- The run's tab is closed after a successful run and kept open after a failure once it started loading Seller Central, or after an interrupt (Ctrl+C exits 130, a termination signal 143) for inspection. `--keep-tab` keeps it after success too.
- The overview's `account` block names the session's selected marketplace `sessionMarketplaceId`. Envelope `url` fields hold the page's origin and path only.
- Diagnostics print URLs without their query string. `tools/discover-poe-endpoints.mjs` redacts session, token and sign-in values in the captures it writes, including meta and input tag values, script assignments, name/value pair objects and JSON stored inside string values, and stores response bodies only for JSON, CSV and GraphQL responses. Key names match by case-insensitive substring, so some harmless keys are redacted too; a customer id key matches only when spelled `customerId`. Two exceptions: `sso` must start a word, and the sign-in keys `code`, `state`, `nonce` and `arb` match only as whole keys. URL fragments are dropped, and every query value of a sign-in URL is redacted. The discovery tool rejects unknown options and attaches only to a known Seller Central origin.
- A niche title with no Latin letters or digits names its files `niche-<niche id>`. CSV cells are not neutralized against spreadsheet formulas, matching POE's own download; the README says how to open them safely.
- Schema ids: `amazon-poe-downloader.envelope.v1`, `amazon-poe-downloader.cri.v1`, `amazon-poe-downloader.returns.v1`, `amazon-poe-downloader.overview.v1` and `amazon-poe-downloader.related-niches.v1`.
- `fetch-poe.js` can also be pasted into the DevTools console of a POE page; its functions are available as `fetchPoeNiche`, `fetchPoeSearch`, `fetchPoeMerchantNiches` and `fetchPoeContext`, and `format-poe.mjs --stdin` turns the result into files.
- Live status: the POE query strings were last checked live on 2026-07-05. This release's code, including its trimmed `GetUserContext` query and the response marketplace and niche id checks, has not been run against live Seller Central yet. Whether the `merchant-niches` response fills the marketplace id its check needs is not confirmed.
